# Aviasales Analytics Kit

Аналитический проект для мониторинга цен на авиабилеты: от получения кэшированных данных Travelpayouts / Aviasales Data API до PostgreSQL и интерактивного дашборда Power BI.

## Power BI dashboard

Дашборд показывает минимальную и медианную цену, число доступных предложений, долю прямых рейсов, динамику цен по датам вылета и детальное сравнение наблюдений по маршрутам.

![Power BI dashboard](docs/images/price_monitoring_dashboard.png)

## Цель проекта

Построить воспроизводимый пайплайн, который позволяет:

- регулярно получать наблюдения о ценах на авиабилеты;
- сохранять исходные ответы API без изменения;
- загружать наблюдения в PostgreSQL;
- отслеживать цены для одних и тех же комбинаций «маршрут × дата вылета»;
- анализировать динамику доступных цен и долю прямых рейсов;
- визуализировать результаты в Power BI;
- развивать проект через dbt-трансформации, дополнительные исследования и интерфейс бота.

## Архитектура


Для ручной обработки локальных файлов также используется:

```text

```

## Возможности

- Сбор цен по фиксированному набору маршрутов и дат вылета.
- Хранение неизменённых API-ответов в JSONL с моментом сбора в UTC.
- Загрузка исходных API-ответов и распакованных наблюдений в PostgreSQL.
- Контроль ошибок: при неуспешном сборе загрузка в БД не запускается.
- Журналирование запусков в `logs/daily_pipeline.log`.
- Power BI-дэшборд с ключевыми показателями, графиком динамики и детальной таблицей.
- Отдельный EDA-ноутбук для анализа разовой исторической выборки.

## Быстрый старт

### 1. Клонирование

```bash
git clone [https://github.com/Filippova-Kristina-Valerianovna/aviasales-analytics-kit.git](https://github.com/Filippova-Kristina-Valerianovna/aviasales-analytics-kit.git)
cd aviasales-analytics-kit
```

### 2. Conda-окружение

```bash
conda create -n aviasales-analytics python=3.13 -y
conda activate aviasales-analytics
pip install -r requirements.txt
```

### 3. Настройка переменных окружения

Создай локальный файл `.env` в корне проекта. Он не должен попадать в Git.

```env
TRAVELPAYOUTS_TOKEN=your_token
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
POSTGRES_DB=aviasales_analytics
POSTGRES_USER=postgres
POSTGRES_PASSWORD=your_password
```

Для доступа к API необходим токен Travelpayouts. Для работы pipeline также должен быть доступен локальный экземпляр PostgreSQL.

### 4. Запуск ежедневного pipeline

В Windows из корня проекта:

```bat
.\run_daily_price_pipeline.bat
```

Скрипт:

1. создаёт `logs/`, если папки нет;
2. запускает сборщик `src\collect_price_panel.py`;
3. прекращает работу при ошибке сборщика;
4. запускает `src\load_price_panel_to_postgres.py`;
5. сохраняет ход выполнения и ошибки в `logs\daily_pipeline.log`.

Для регулярного запуска BAT-файл можно добавить в Планировщик заданий Windows.

## Данные и мониторинг

Панель собирает наблюдения по фиксированным комбинациям маршрутов и дат вылета. Такой подход позволяет сравнивать изменения доступных цен во времени при неизменных параметрах поездки.

Текущая панель включает следующие маршруты:

- `KZN → AER`
- `LED → KZN`
- `MOW → AER`
- `MOW → LED`
- `SVX → OVB`

Фиксированные даты вылета:

- 15 ноября 2026 года;
- 15 декабря 2026 года;
- 15 января 2027 года.

На каждом запуске сохраняется момент наблюдения `collected_at` в UTC. Пустой ответ API означает, что для комбинации маршрута и даты на момент запроса не нашлось предложения в кэше; он не интерпретируется как цена 0.

## PostgreSQL

Pipeline загружает данные в PostgreSQL в два слоя:

| Слой | Таблица | Назначение |
|---|---|---|
| Raw | `raw.travelpayouts_responses` | Неизменённые ответы API и метаданные запроса |
| Staging | `staging.flight_price_observations` | Распакованные ценовые наблюдения для анализа и Power BI |

Такое разделение сохраняет исходные данные для аудита и даёт удобную табличную основу для аналитики.

## Power BI

Дашборд подключается к подготовленным данным и позволяет фильтровать наблюдения по:

- маршруту;
- дате вылета;
- валюте.

Основные показатели:

- минимальная цена;
- медианная цена;
- число доступных предложений;
- доля прямых рейсов;
- динамика медианной цены по датам вылета;
- таблица для сравнения предложений.

После нового запуска pipeline обнови набор данных в Power BI, чтобы отобразить новые наблюдения.

## EDA: разовая выборка

Первое исследование проекта доступно в ноутбуке [`notebooks/02_flight_prices_eda.ipynb`](notebooks/02_flight_prices_eda.ipynb).

Исследование рассматривает разовую выборку цен и изучает связь цены с маршрутом, числом пересадок и горизонтом бронирования. В исторической выборке было 305 предложений на 41 маршруте; период вылета — с 9 октября 2026 года по 31 января 2027 года, валюта — RUB.

### Ключевые результаты EDA

- Диапазон цен: от 4 480 ₽ до 43 772 ₽.
- Медианная цена: 14 593 ₽; средняя цена: 15 155 ₽.
- Прямые рейсы составили 83,0% выборки.
- В доступной выборке наиболее высокая медианная цена наблюдалась в когорте 90 дней до вылета — 19 640 ₽.

Эти результаты описывают одну выгрузку и не доказывают причинно-следственных связей. Для анализа динамики необходимы регулярные наблюдения, которые собирает ценовая панель.

## Ограничения данных

Aviasales Data API отдаёт цены из кэша поисковой истории пользователей, а не данные о подтверждённых бронированиях. По документации Travelpayouts, данные кэшируются, а сроки хранения для разных запросов могут составлять от 2 до 7 дней. Поэтому проект анализирует изменения доступных кэшированных цен, а не фактические продажи или рыночную цену в реальном времени.

- Пустой API-ответ не означает отсутствия рейсов или нулевую цену.
- Наличие цены не гарантирует, что предложение всё ещё доступно для покупки.
- Результаты зависят от покрытия кэша, параметров API и времени сбора.
- Наблюдаемые различия между маршрутами, пересадками и датами не следует трактовать как доказательство причинности.

Подробнее: [Aviasales Data API](https://support.travelpayouts.com/hc/en-us/articles/203956163-Aviasales-Data-API).
