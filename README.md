# Aviasales Analytics Kit

Портфолио-проект на данных Travelpayouts / Aviasales Data API: сбор цен на авиабилеты, хранение в PostgreSQL, аналитические преобразования, визуализация в Power BI и Telegram-бот для поиска и мониторинга маршрутов.

Проект объединяет два сценария:

- аналитический: накопить наблюдения и сравнивать доступные цены по маршрутам, датам вылета и датам сбора;
- пользовательский: найти предложения через Telegram, сохранить интересные варианты и добавить маршрут в мониторинг.

Проект запускается локально на ноутбуке. Постоянное серверное размещение в текущую версию не входит.

## Результат проекта

- Сбор ответов API по фиксированным маршрутам и датам вылета.
- Сохранение исходных ответов в JSONL и PostgreSQL.
- Аналитические слои raw, staging и marts.
- dbt-модели и проверки данных.
- Два листа Power BI: обзор цен и динамика выбранной поездки.
- Исследовательский анализ разовой выборки в Jupyter Notebook.
- Telegram-бот с поиском, избранным и мониторингом маршрутов.
- Хранение пользователей, поисковых запросов и настроек бота в PostgreSQL.

Это  портфолио-проект, а не официальный продукт Aviasales.

## Power BI

### Price Monitoring

Обзор доступных цен, числа предложений и доли прямых рейсов. Фильтры позволяют выбрать маршрут, дату вылета и валюту.
[Посмотреть скриншот Price Monitoring](docs/images/price_monitoring_dashboard.png)
Основные показатели:

- минимальная и медианная цена;
- число доступных предложений;
- доля прямых предложений;
- сравнение цен по датам вылета;
- детализация наблюдений.

Скриншот показывает один из сохранённых вариантов состояния отчёта. Набор мониторинга включает пять маршрутов.

### Динамика цен

История медианной цены для выбранной комбинации «маршрут × дата вылета».
[Посмотреть скриншот динамики цен](docs/images/price_dynamics_dashboard.png)
На странице представлены:

- медианная цена на последнюю доступную дату сбора;
- изменение к предыдущему доступному наблюдению в рублях и процентах;
- история медианных цен;
- тепловая матрица по маршрутам, датам вылета и датам сбора.

Сравнение выполняется между последними доступными наблюдениями, а не обязательно между соседними календарными днями.

Изменение медианы не означает изменение стоимости одного и того же билета: состав предложений API между сборами может различаться. Цвет ячеек матрицы показывает уровень цены, а не направление её изменения.

Рабочий файл Power BI хранится локально:

`dashboards/aviasales_price_dashboard.pbix`

Файлы `.pbix` исключены из Git. После нового сбора данных отчёт нужно обновить в Power BI.

Скриншоты находятся в `docs/images/`:

- `price_monitoring_dashboard.png`;
- `price_dynamics_dashboard.png`.

## Telegram-бот

Бот использует ту же локальную базу PostgreSQL, но хранит пользовательские данные отдельно, в схеме `flight_bot`.

### Возможности

- Поиск доступных предложений по маршруту и дате.
- Поиск городов по названию, сокращению или коду.
- Уточнение города через выбор из списка.
- Сохранение предложений в избранное.
- Добавление маршрута в мониторинг с порогом цены.
- Просмотр сохранённых маршрутов и последней найденной цены.
- Ручной запуск проверки маршрутов.
- Фоновая проверка активных маршрутов.
- Создание и просмотр подписок на конкретную дату.

В текущей конфигурации фоновая задача мониторинга маршрутов запланирована каждые шесть часов, первый запуск — через 30 секунд после старта бота. Это расписание работает только при запущенном приложении.

### Подписки и мониторинг маршрутов

Это два разных сценария:

| Сценарий | Текущий статус |
|---|---|
| Мониторинг маршрута в пределах горизонта поиска | Подключены ручная и фоновая проверки |
| Подписка на конкретную дату | Реализованы создание, проверка ввода, сохранение и просмотр |
| Автоматическая проверка подписок на дату | Не входит в подтверждённую готовность текущей версии |

Создание подписки само по себе не означает, что для неё уже работает автоматическая отправка уведомлений.

### Таблицы бота

| Таблица | Назначение |
|---|---|
| `flight_bot.users` | Пользователи и идентификаторы чатов |
| `flight_bot.search_requests` | История запросов, результаты и статусы поиска |
| `flight_bot.favorites` | Сохранённые предложения |
| `flight_bot.monitored_routes` | Маршруты и настройки мониторинга |
| `flight_bot.subscriptions` | Подписки на конкретную дату |

## Данные и методика

### Панель мониторинга

Наблюдения собираются для фиксированных комбинаций маршрута и даты вылета. Это позволяет сравнивать доступные предложения во времени при одинаковых параметрах поездки.

Маршруты:

- KZN → AER;
- LED → KZN;
- MOW → AER;
- MOW → LED;
- SVX → OVB.

Даты вылета в текущей конфигурации панели:

- 15 ноября 2026 года;
- 15 декабря 2026 года;
- 15 января 2027 года.

Для каждого сбора фиксируется `collected_at` в UTC. Даты и маршруты описывают конфигурацию этой версии, а не универсальный набор для любого периода.

Пустой ответ API не считается нулевой ценой и не доказывает отсутствие рейсов.

### Аналитические слои PostgreSQL

| Слой | Объект | Назначение |
|---|---|---|
| Raw | `raw.travelpayouts_responses` | Исходные ответы API и метаданные запросов |
| Staging | `staging.flight_price_observations` | Подготовленные ценовые наблюдения |
| Marts | `marts.mart_price_monitoring_daily` | Дневная витрина для Power BI |

Витрина агрегирует показатели по маршруту, дате вылета, валюте и дате сбора:

- минимальную, медианную и среднюю цену;
- число доступных предложений;
- число и долю прямых предложений;
- среднюю длительность;
- среднее число пересадок;
- минимальный и максимальный горизонт до вылета.

Исходные ответы сохраняются отдельно от аналитического слоя.

## Исследовательский анализ

Ноутбук: `notebooks/02_flight_prices_eda.ipynb`.

Первое исследование посвящено разовой исторической выборке, а не накопленной панели мониторинга.

Характеристики выборки:

- 305 предложений;
- 41 маршрут;
- даты вылета с 9 октября 2026 года по 31 января 2027 года;
- валюта RUB.

Результаты, зафиксированные в исследовании:

| Показатель | Значение |
|---|---:|
| Минимальная цена | 4 480 ₽ |
| Максимальная цена | 43 772 ₽ |
| Медианная цена | 14 593 ₽ |
| Средняя цена | 15 155 ₽ |
| Доля прямых рейсов | 83,0% |

Эти результаты описывают конкретную выгрузку. Они не доказывают, что определённый срок покупки вызывает рост или снижение цены. Для изучения динамики используется отдельная панель повторных наблюдений.

## Локальный запуск

Текущая рабочая конфигурация: Windows, Conda, Python 3.13 и локальный PostgreSQL.

### Настройки окружения

В корне проекта используется локальный `.env`:

```env
TRAVELPAYOUTS_TOKEN=your_travelpayouts_token
BOT_TOKEN=your_telegram_bot_token

POSTGRES_HOST=localhost
POSTGRES_PORT=5432
POSTGRES_DB=aviasales_analytics
POSTGRES_USER=postgres
POSTGRES_PASSWORD=your_password
```

Используйте собственные токены и пароль. `.env` исключён из Git.

### Зависимости бота

Для бота подготовлен отдельный файл:

```cmd
python -m pip install -r bot\requirements.txt
```

Основные библиотеки:

- `python-telegram-bot[job-queue]`;
- `python-dotenv`;
- `psycopg[binary]`;
- `requests`;
- `rapidfuzz`.

Корневой `requirements.txt` содержит локальные пути из текущего Conda-окружения и пока не является переносимой инструкцией установки аналитической части.

### Подготовка базы

Для запуска необходимы существующая база PostgreSQL и таблицы соответствующих подсистем.

`bot/db.py` создаёт только таблицы пользователей и поисковых запросов. Он не является полной миграцией всей схемы `flight_bot`.

Полное развёртывание базы с нуля пока не оформлено единой командой. Команды ниже предназначены для настроенной локальной базы проекта.

Проверка подключения:

```cmd
python bot\check_db.py
```

### Запуск бота

Из корня проекта:

```cmd
conda activate aviasales-analytics
python bot\bot.py
```

В Telegram отправьте `/start`.

Для остановки используйте `Ctrl+C`.

### Запуск аналитической обработки

В настроенном локальном окружении, из корня проекта:

```cmd
run_daily_price_pipeline.bat
```
Скрипт последовательно выполняет:

1. Сбор ответов API через `src/collect_price_panel.py`.
2. Загрузку данных в PostgreSQL через `src/load_price_panel_to_postgres.py`.
3. Проверки данных через `dbt_local.bat test`.

При ошибке любого этапа выполнение прекращается, а причина записывается в журнал. Успешное завершение означает, что команды отработали без ошибок и проверки dbt прошли; оно само по себе не гарантирует наличие новых предложений API.

Этот BAT-файл запускает проверки dbt, но не содержит отдельной команды сборки моделей `dbt run` или `dbt build`.

В текущем BAT-файле указан локальный путь к Conda:
`C:\Anaconda\condabin\conda.bat`.
При запуске на другом компьютере путь и название окружения нужно проверить.

Журнал выполнения:

`logs/daily_pipeline.log`

Для регулярного запуска используется Планировщик заданий Windows. Его выполнение зависит от доступности ноутбука и настроек задачи.

Сбор данных и работа Telegram-бота — отдельные процессы.

## Ограничения

### Источник данных

Aviasales Data API возвращает кэшированные результаты пользовательских поисков. Проект не использует данные о фактических продажах или подтверждённых бронированиях.

- Цена из API не гарантирует доступность предложения в момент покупки.
- Пустой ответ не означает отсутствие рейсов или цену 0.
- Покрытие зависит от параметров запроса и содержимого кэша.
- Изменение агрегированной цены может отражать изменение состава предложений.
- Наблюдаемые связи не следует интерпретировать как доказанную причинность.

### Локальная работа

- Бот доступен только при запущенном процессе Python.
- Для фоновых проверок ноутбук должен быть включён, не находиться в спящем режиме и иметь доступ к интернету и PostgreSQL.
- Круглосуточная доступность не гарантируется.
- Автоматическое восстановление пропущенных проверок после простоя не заявлено.
- Обновление отчёта Power BI выполняется отдельно от сбора данных.

### Воспроизводимость

- Подготовлен отдельный список основных зависимостей бота.
- Полная установка аналитического окружения с нуля требует доработки.
- Единый комплект миграций всех таблиц бота пока не подготовлен.
- Сырые выгрузки, локальная база, резервные копии и рабочий `.pbix` не публикуются как часть репозитория.

## Безопасность

В репозиторий не следует добавлять:

- токены Telegram и Travelpayouts;
- пароли PostgreSQL и заполненный `.env`;
- резервные копии базы;
- выгрузки с идентификаторами пользователей и чатов.


## Статус проекта

Текущая версия объединяет аналитический контур и локальный Telegram-бот. Серверное размещение намеренно не входит в объём этой версии.

Возможные дальнейшие улучшения, не являющиеся условием завершения портфолио-версии:

- единая инструкция установки аналитических зависимостей;
- миграции базы для развёртывания с нуля;
- автоматическая проверка подписок на конкретную дату;
- автоматические тесты пользовательских сценариев;
- проверка восстановления резервной копии;
- показатели покрытия данных и качества сборов.
